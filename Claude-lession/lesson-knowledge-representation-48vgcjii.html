🧠 Biểu diễn Kiến thức trong AI

Knowledge Representation - Nền tảng của Hệ thống Chuyên gia

📚 Định nghĩa Cơ Bản

✅ Kiến thức (Knowledge) là thứ được lưu trữ trong đầu chúng ta, đại diện cho sự hiểu biết về thế giới.

Kiến thức được tạo thành bằng cách học tập chủ động, tích hợp những mẩu thông tin mà chúng ta nhận được vào mô hình thế giới của mình.
🔄 Tháp DIKW: Mô hình phân cấp hiểu biết

📊 Data → được biểu diễn trên phương tiện vật lý (text, âm thanh)
💡 Information → cách chúng ta diễn giải dữ liệu trong đầu
🧠 Knowledge → thông tin tích hợp vào mô hình thế giới
✨ Wisdom → hiểu biết meta (khi nào dùng kiến thức)

🎯 4 Cách Biểu Diễn Kiến Thức Khác Nhau

1️⃣ Biểu Diễn Thuật Toán (Algorithmic)

Kiến thức được biểu diễn dưới dạng một chương trình máy tính

def is_carnivore(animal): if animal.eats_meat: return True if animal.has_sharp_teeth and animal.has_claws: return True return False

💾 Ví dụ Dữ Liệu:

Tốt: Data có cấu trúc rõ ràng, luôn lặp lại (Mèo ăn thịt)
Xấu: Luật ngoại lệ nhiều, khó mã hóa hết (Cá heo ăn cá nhưng không phải cá)

✅ Ưu: Nhanh, dễ kiểm soát ❌ Nhược: Cứng nhắc, khó mở rộng

2️⃣ Mạng Ngữ Nghĩa (Semantic Network)

Mô phỏng mạng khái niệm liên kết trong đầu người

Chim (Bird) ├─ thuộc: Động vật có xương sống (Vertebrate) ├─ có: Cánh (Wings) └─ có: Lông vũ (Feathers) Canary (Chim hoắc ca) ├─ là loại: Chim (Bird) ├─ màu: Vàng (Yellow) └─ có thể: Bay nhanh (Fast flight) Mối Liên Kết: Canary → [is-a] → Bird → [has] → Wings

💾 Ví dụ Dữ Liệu:

Tốt: Hiển thị mối quan hệ phức tạp, dễ mở rộng (Thêm động vật mới)
Xấu: Có thể có mâu thuẫn, cần xử lý cẩn thận

✅ Ưu: Linh hoạt, gần với cách suy nghĩ con người ⚠️ Nhược: Có thể chậm khi dữ liệu lớn

3️⃣ Biểu Diễn Frame (Frame Representation)

Mỗi đối tượng là một khung với các khe (slots) chứa thông tin

# Frame cho Chim Hoắc Ca (Canary) class Canary: is_a = "Bird" # Slot: loại color = "Yellow" # Slot: màu sắc can_fly = True # Slot: bay được habitat = "South America" # Slot: nơi sống size = "Small" # Slot: kích thước # Giá trị mặc định @default wings = 2 # Mặc định: 2 cánh

💾 Ví dụ Dữ Liệu:

Tốt: Dữ liệu có cấu trúc, dễ bảo trì (Tất cả chim có cánh)
Xấu: Slot trống, mâu thuẫn giữa các frame (Chim cánh cụt không bay)

✅ Ưu: Cấu trúc rõ ràng, giá trị mặc định hữu ích ⚠️ Nhược: Khó xử lý phức tạp, thừa dữ liệu

4️⃣ Biểu Diễn Logic (Logic-based)

Sử dụng quy tắc logic hình thức (Production Rules)

// Quy tắc 1: Nếu ăn thịt → là động vật ăn thịt IF eats_meat(X) THEN carnivore(X) // Quy tắc 2: Nếu (có răng sắc + có móng + mắt hướng về phía trước) IF has_sharp_teeth(X) AND has_claws(X) AND forward_eyes(X) THEN carnivore(X) // Quy tắc 3: Áp dụng cho Canary eats_insects(Canary) → eats_meat(Canary) → carnivore(Canary)

💾 Ví dụ Dữ Liệu:

Tốt: Dữ liệu tuân theo quy tắc logic, có thể chứng minh (Lập luận từng bước)
Xấu: Dữ liệu không đầy đủ, mâu thuẫn logic

✅ Ưu: Có thể chứng minh, giải thích được kết quả ❌ Nhược: Tính toán phức tạp, có thể không hội tụ

📊 Bảng So Sánh 4 Cách

Cách Biểu Diễn Input Xử Lý Output Độ Phức Tạp
Algorithmic Đặc tính động vật Chạy hàm logic Carnivore? (Yes/No) O(1) - ⚡ Nhanh
Semantic Network Nút & cạnh đồ thị Duyệt đồ thị (BFS/DFS) Tất cả thuộc tính liên quan O(V+E) - 🚶 Trung bình
Frame Tên frame + slots Tra cứu bảng hash Giá trị slot + mặc định O(1) - ⚡ Nhanh
Logic-based Sự kiện & quy tắc Suy diễn (Forward/Backward) Chứng minh logic + giải thích O(2^n) - 🐢 Chậm

🔄 2 Cách Suy Diễn: Forward vs Backward

➡️ Forward Inference (Suy diễn Tới)

Bắt đầu với dữ liệu đầu vào, áp dụng quy tắc để có kết luận

Dữ Liệu Ban Đầu: ├─ eats_insects(Canary) ✓ ├─ has_sharp_teeth(Canary) ✓ └─ has_claws(Canary) ✓ ⬇️ [Áp dụng quy tắc] Kết Luận: ├─ eats_meat(Canary) ✓ ├─ has_sharp_teeth(Canary) ✓ └─ carnivore(Canary) ✓

✅ Tốt cho: Chẩn đoán bệnh, phân loại động vật, kiểm tra dữ liệu đầu vào sẵn có

⬅️ Backward Inference (Suy diễn Lùi)

Bắt đầu với mục tiêu cần đạt, tìm quy tắc & dữ liệu để chứng minh

Mục Tiêu: carnivore(Canary) = ? ⬆️ [Tìm quy tắc] Cần chứng minh: ├─ eats_meat(Canary) = ? ├─ has_sharp_teeth(Canary) = ? └─ has_claws(Canary) = ? ⬆️ [Hỏi dữ liệu] Dữ Liệu: ✓ eats_insects(Canary) = TRUE ✓ has_sharp_teeth(Canary) = TRUE → Chứng minh thành công!

✅ Tốt cho: Trò chơi suy luận logic, lý thuyết định lý, trả lời câu hỏi cụ thể

🌍 Use Cases Thực Tế

🏥 Hệ thống Chẩn đoán Bệnh

Cách sử dụng: Forward Inference + Production Rules

Quy tắc: IF (sốt cao OR protein phản ứng cao) THEN viêm nhiễm

Input tốt: Kết quả xét nghiệm, biểu hiện lâm sàng rõ ràng

Input xấu: Triệu chứng mơ hồ, dữ liệu không đầy đủ

🎮 Trò Chơi Tương Tác

Cách sử dụng: Backward Inference + Semantic Network

Quy tắc: Người chơi hỏi "Động vật này là gì?", hệ thống hỏi lại câu hỏi

Input tốt: Câu trả lời rõ ràng (Yes/No)

Input xấu: Câu trả lời không rõ (Có thể, hơi..., không chắc...)

📚 Hệ Thống Gợi Ý (Recommender)

Cách sử dụng: Frame Representation + Semantic Network

Quy tắc: Nếu người dùng thích sách A và sách A giống sách B → gợi ý sách B

Input tốt: Lịch sử mua hàng, đánh giá rõ ràng

Input xấu: Người dùng mới, dữ liệu thưa thớt

⚖️ Hệ Thống Tư Pháp

Cách sử dụng: Logic-based + Production Rules

Quy tắc: IF (vi phạm luật AND có bằng chứng) THEN xử phạt

Input tốt: Bằng chứng chắc chắn, mô tả rõ ràng sự kiện

Input xấu: Bằng chứng gián tiếp, mâu thuẫn pháp lý

Bài Tập: Thiết Kế Frame cho "Phương Tiện Giao Thông"

Hãy tạo một Frame representation cho các loại phương tiện giao thông:

class Vehicle: # Điền vào các slot này: name = ___________ # Ví dụ: "Ô tô", "Xe máy" is_a = ___________ # Loại: Phương tiện wheels = ___________ # Số bánh max_speed = ___________ # Tốc độ tối đa (km/h) fuel_type = ___________ # Loại nhiên liệu capacity = ___________ # Số chỗ ngồi cost = ___________ # Giá tiền # Giá trị mặc định: @default requires_license = True @default pollutes = True

💡 Gợi ý: Điền vào 3 loại phương tiện khác nhau (Ô tô, Xe máy, Xe đạp)

✨ Gợi Ý: 
Vehicle-Ô tô: wheels=4, max_speed=200, capacity=5
Vehicle-Xe máy: wheels=2, max_speed=120, capacity=2
Vehicle-Xe đạp: wheels=2, max_speed=30, capacity=1

🎯 Kết Luận

Khi Dùng Cách Nào?

✅ Algorithmic: Khi quy tắc ít, cố định, cần tốc độ

✅ Semantic Network: Khi có mối quan hệ phức tạp, cần mở rộng linh hoạt

✅ Frame: Khi dữ liệu cấu trúc rõ ràng, có giá trị mặc định chung

✅ Logic-based: Khi cần chứng minh, giải thích kết luận
